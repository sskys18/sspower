◆Overview

sspower is a standalone skill framework for Claude Code. It layers a skill router, a Codex CLI bridge, lifecycle hooks, and a memory backend on top of the plain agent loop — turning ad-hoc prompting into gated, reviewable workflows.

🧩Skills

22 on-demand workflow modules. A meta-router (using-sspower) fires every turn and pulls in any skill that matches — even at 1% probability.

🪝Hooks

13 lifecycle hooks across SessionStart, UserPromptSubmit, PreToolUse, PostToolUse, PreCompact and SessionEnd — they inject context, rewrite commands, and gate risky actions.

🤖Codex bridge

scripts/codex-bridge.mjs drives the OpenAI Codex CLI directly for independent review and implementation — no extra plugin.

🛡️Review gates

Five review checkpoints between writing code and merging. Codex gates block git push / PR on a non-approve verdict.

🧠Memory

sspower-mem archives every session; skills recall prior decisions and gotchas before proposing new work.

🥗Diet mode

Token-efficient output mode, reinforced per turn, with three sub-skills for commits, reviews and memory compression.

↻Hook Lifecycle

Hooks are registered in hooks/hooks.json and fire on Claude Code lifecycle events. This is the order of events across one turn.

SessionStart
session-start boots state dirs & wiki link · diet-activate.js turns on diet mode (default full) · semble-session.sh checks tooling and warms models.
▼
UserPromptSubmit
prompt-submit injects project memory + global rules · diet-track.js reinforces diet · codex-track-prompt.sh surfaces running Codex sessions · semble-context.sh injects repo orientation on coding intent.
▼
PreToolUse : Bash
Runs in order. semble-rewrite.sh rewrites ls -R / grep -R to semble_rs → cmd-rewrite.sh applies the rtk token-saver to every other command → auto-spec-gate.sh gates SDD chokepoints → auto-review.sh gates git/gh chokepoints.
▼
PostToolUse : Write | Edit | MultiEdit
codex-lsp-posttool.sh runs a de-fanged advisory LSP pass on Claude's just-edited file — diagnostics surface as context, never block.
▼
PreCompact / SessionEnd
wiki-archive.sh archives the session into sspower-mem as an episodic memory block + a JSON sidecar.

Session registry

Every persistent run writes a state record + an append-only event log under ~/.claude/state/sspower/codex/. States move running → done | failed | killed; stale zombies are detected via kill -0.

codex-bridge.mjs ps                        # all active + recent
codex-bridge.mjs status <id>               # JSON state record
codex-bridge.mjs tail   <id>               # stream events live
codex-bridge.mjs kill   <id>               # SIGTERM, mark killed
codex-bridge.mjs steer  --session-id <id> --prompt <p>   # kill + resume
Canonical source Claude Code loads the marketplace tree (~/.claude/plugins/marketplaces/sskys18/plugins/sspower/). The ~/.codex/plugins/cache/… copy is stale — never edit or rely on it.

🔒Sandbox & Security

Every Codex exec runs under a Seatbelt sandbox. There is no danger-full-access path in sspower — by design.

ModeFilesystemNetwork
read-onlyreads anywhere; no writesnone
workspace-writewrites confined to the cwd subtreeconfigurable

Defense-in-depth layers

🧱Hardened write profile

On --write, the bridge appends approval_policy=never and network_access=false — also re-applied on every write-capable resume (a resumed session does not inherit the network knob).

📸autoCommit guards

--auto-commit refuses if HEAD changed during the run, or if a planted MERGE_HEAD / CHERRY_PICK_HEAD / etc. exists — preventing tainted commit parents.

🚧PreToolUse guard

The Codex worker's PreToolUse hook classifies commands — deny for git commit/push/merge & recursive rm, ask for installs. Cooperative-worker scope; the sandbox is the real perimeter.

🔁Loop guards

Auto-review is bounded by a re-entry flag, depth counter, 10-min verdict cache, and a 3-round hard cap per branch.

🛡️Review Gates

Five review checkpoints sit between writing code and merging. Three skills enforce Codex review early (HARD-GATEs); the auto-review.sh hook is the last line at the push surface.

#GateWhoWhen
1Self-reviewImplementerPer task
2Spec complianceClaude or CodexPer task
3Code qualityClaude or CodexPer task
4Final reviewClaude code-reviewerAll tasks
5Second opinionCodex (independent)Before merge

The push gate — auto-review.sh

Intercepts git push, git merge, gh pr create, gh pr ready. Runs Codex review on the BASE..HEAD diff and blocks unless the verdict is approve or approve-with-followups.

Chain policy — security-critical Chokepoints must run as standalone Bash invocations. Predecessors joined with && || ; & are denied (they could mutate state before review). Only read-only output pipes (| tail, | grep, | jq …) are allowed after. Bypass for emergencies: SSPOWER_AUTO_REVIEW=off.

🧠Project Memory

Every session is archived (PreCompact + SessionEnd) into sspower-mem as an episodic block, plus a JSON sidecar under <cwd>/.claude/wiki/sessions/ (legacy belt).

brainstorming, writing-plans, systematic-debugging and using-sspower read and write decisions + gotchas through the sspower-mem CLI — so prior context informs every new design and bug investigation. session-start injects recent project memory back into context via sspower-mem search --mode recent.

Exit-code contract All sspower-mem calls normalize exit codes: 0 ok · 10 degraded (continue) · 20 hard data-loss (propagates) · 30 dependency missing (continue empty).

📊Observability

The bridge and hooks write one event per line to a single rotating log — ~/.claude/sspower/codex.log (rotates at 1000 lines, keeps 500).

2026-04-23T14:22:01Z [error] bridge.enrich kind="schema_parse_fail" …
2026-04-23T14:22:33Z [warn]  hook.enrich  kind=timeout dur=31s …
2026-04-23T14:22:50Z [info]  hook.enrich  kind=enriched dur=18s …

During runs, a live event stream renders on stderr — [codex:session], [codex:tool], [codex:edit], [codex:token], [codex:alive] (30s heartbeat), [codex:done]. Say "examine codex log" or invoke the codex-diagnostics skill to group errors and propose patches.
